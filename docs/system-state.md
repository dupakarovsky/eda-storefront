## Infrastructure

| Component            | Status | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `docker-compose.yml` | Live   | Postgres 17 + NATS 2.12 (JetStream) + `stores`, each on a pinned-subnet `eda-net` bridge network, ports bound to `127.0.0.1` only. `stores` builds from `stores/Dockerfile` (two-stage: `golang:1.25` → `alpine:3.20`), reaches Postgres/NATS by internal service name/port via `environment:` overrides layered on `env_file`. Grows by one service block per project from here.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| NATS (JetStream)     | Live   | `EnsureStream` uses explicit `FileStorage`; durability across container restart confirmed. **No Docker healthcheck** — `nats:2.12`'s official image has no shell or utilities capable of running one (confirmed by direct experimentation); startup-ordering safety instead comes from `foundation/nats`'s `RetryOnFailedConnect(true)`, which also covers NATS restarting independently of `stores`, something a healthcheck-gated `depends_on` alone would never help with. "Every publisher now attaches a per-call Nats-Msg-Id, reusing the same ID across all retry attempts of one logical publish (ADL 0015) — relying on each stream's default 2-minute Duplicate Window to collapse retry-driven duplicate arrivals into a single stored message. Discovered via baskets' Phase 3 NATS-restart retry test (a real stream-content check revealed 3 stored messages for what should have been 1 logical publish), backported to stores the same day." |
| Postgres             | Live   | Hardened baseline per ADL 0006. `edadb` (foundation smoke-testing) and `storesdb` (owned by `stores`, provisioned via `03-stores-db.sh`) both live on this instance; one database per service as each is added. Real `pg_isready`-based Docker healthcheck gates `depends_on` for every dependent service.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `Makefile`           | Live   | Reorganized into deployment (`up`/`down`/`build`/`logs`/`ps`, migrations) vs. development-only (`stores/run`, `foundation/smoke`, `storesdb/dev`) sections. `stores/run` remains a fast local-iteration path (bare `go run`, not containerized) — `system-state.md`'s "Live" status for `stores` reflects what `make up` produces, not `stores/run`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## How to update this file

At the **start** of a project: confirm every service listed as a live dependency
in `docs/roadmap.md`'s project table is actually marked "Live" here before
beginning. If it isn't, stop and reconcile before writing any code.

At the **end** of a project: flip the new service(s) from "Not started" (or "In
progress") to "Live," fill in real published/consumed event names (the TBD
placeholders above are guesses from the source book, not commitments), and
update "Last Updated" for every row that changed.
